# 16. Advanced Internal Questions
 * `1. Explain HashMap internals in Java 8 step by step.`
    In Java 8, `HashMap` is implemented using an **array of buckets**, where each bucket holds either a **singly linked list** or a self-balancing **Red-Black Tree** to store key-value pairs (`Node<K,V>` or `TreeNode<K,V>`).

---

### 1. Core Data Structures & Constants

* **Bucket Array (`Node<K,V>[] table`):** The primary backing array.
* **`DEFAULT_INITIAL_CAPACITY`:** `16` ($2^4$). Always a power of 2.
* **`DEFAULT_LOAD_FACTOR`:** `0.75`. Controls when the table resizes.
* **`TREEIFY_THRESHOLD`:** `8`. When collisions in a single bucket reach 8 nodes, it converts to a Red-Black Tree.
* **`UNTREEIFY_THRESHOLD`:** `6`. When a tree bucket shrinks to 6 nodes during resize/removal, it reverts to a linked list.
* **`MIN_TREEIFY_CAPACITY`:** `64`. A bucket will treeify only if the total array capacity is at least 64; otherwise, it resizes the array instead.

---

### 2. Step 1: Calculating the Hash (Perturbation Function)

When you pass a key, Java first calls `key.hashCode()` and applies a bitwise shift/XOR operation:

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

```

* **Why the XOR and shift?** It mixes the high 16 bits into the low 16 bits. Since table sizes are small powers of 2 (e.g., 16), only the lower bits determine the index. This mixing drastically reduces collisions from poor `hashCode()` implementations.

---

### 3. Step 2: Finding the Bucket Index

The bucket index is calculated using a bitwise AND instead of modulo:

$$\text{index} = (n - 1) \ \& \ \text{hash}$$

*(Where $n$ is the current table length, which is always a power of 2).*

* Because $n$ is a power of 2, $(n - 1) \ \& \ \text{hash}$ is mathematically equivalent to $\text{hash} \pmod n$, but runs in a single CPU cycle.

---

### 4. Step 3: Inserting Data (`put(K, V)`)

```text
put(key, value)
  │
  ├── 1. Array empty/null? ──► Initialize array (resize to capacity 16).
  │
  ├── 2. Bucket empty? ──► Create new Node<K,V> at table[index].
  │
  └── 3. Collision occurs (table[index] not empty):
        │
        ├── Key matches first node (same hash && (k == key || key.equals(k)))?
        │     └── Overwrite existing value.
        │
        ├── Is bucket a TreeNode?
        │     └── Insert into Red-Black Tree (O(log n)).
        │
        └── Is bucket a standard LinkedList?
              ├── Traverse to tail (append node at the end - tail insertion).
              ├── If matching key found during traversal, overwrite value.
              └── If node count reaches 8:
                    ├── If table.length < 64 ──► Resize array instead.
                    └── If table.length >= 64 ──► Convert bucket to Red-Black Tree.

```

---

### 5. Step 4: Retrieving Data (`get(K)`)

1. Compute `hash = hash(key)` and locate `table[(n - 1) & hash]`.
2. Check the first node in the bucket:
* If `first.hash == hash` and `(first.key == key || key.equals(first.key))`, return `first.value`.


3. If not matched:
* If it's a `TreeNode`, search the Red-Black Tree in **$O(\log n)$** time.
* If it's a `Node`, traverse the linked list in **$O(n)$** time.


4. If no match is found after traversing, return `null`.

---

### 6. Step 5: Resizing & Rehashing (`resize()`)

When `size > threshold` ($\text{capacity} \times \text{load\_factor}$, e.g., $16 \times 0.75 = 12$), the array doubles in capacity ($16 \rightarrow 32$).

**Java 8 Optimization (No full re-indexing):**

* Because capacity doubles ($2^x$), a node's new index in the doubled table is either:
* Its **same old index** (`oldIndex`)
* **Old index + old capacity** (`oldIndex + oldCap`)


* Java 8 checks the new bit using `(e.hash & oldCap) == 0`:
* If `0` $\rightarrow$ stays at `oldIndex`.
* If `!= 0` $\rightarrow$ moves to `oldIndex + oldCap`.


* It preserves the original relative order (no reverse-order insertion), which eliminates the infamous Java 7 **infinite loop / cyclic dependency** bug during concurrent resizes.

# 2. Explain ArrayList internals in Java 8.

`ArrayList` in Java is a resizable, index-based list backed by a standard **Object array (`transient Object[] elementData`)**.

It provides fast random access by index and dynamically grows its underlying array when capacity runs out.

---

### 1. Key Fields & Constants in Java 8

* `transient Object[] elementData`: The internal buffer array where elements are stored.
* `private int size`: The number of elements currently stored in the list.
* `DEFAULT_CAPACITY = 10`: The initial capacity assigned when elements are first added to an empty list.
* `DEFAULTCAPACITY_EMPTY_ELEMENTDATA = {}`: A shared empty array used when `new ArrayList<>()` is instantiated without parameters.
* `EMPTY_ELEMENTDATA = {}`: A shared empty array used when `new ArrayList<>(0)` is explicitly initialized with a capacity of 0.

---

### 2. Initialization & Lazy Allocation

In Java 8, instantiating `new ArrayList<>()` uses **lazy allocation** to save heap memory:

```java
public ArrayList() {
    this.elementData = DEFAULTCAPACITY_EMPTY_ELEMENTDATA;
}

```

* Creating an `ArrayList` allocates **no heap memory** for the internal array initially.
* Memory allocation for the default capacity of **10** is deferred until the very first call to `.add()`.

---

### 3. Adding Elements & Growth Formula (`grow()`)

When you call `list.add(element)`:

1. It verifies whether `size + 1` exceeds `elementData.length`.
2. If full, it calls `grow(minCapacity)`.

```java
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;
    // New capacity = oldCapacity + (oldCapacity >> 1)  --> 1.5x (50% growth)
    int newCapacity = oldCapacity + (oldCapacity >> 1);
    
    if (newCapacity - minCapacity < 0)
        newCapacity = minCapacity;
    if (newCapacity - MAX_ARRAY_SIZE > 0)
        newCapacity = hugeCapacity(minCapacity);
        
    // Native array copy to the new larger array
    elementData = Arrays.copyOf(elementData, newCapacity);
}

```

* **Growth Factor:** The array expands by **50% ($1.5\times$)** of its current capacity using bitwise right-shift (`oldCapacity + (oldCapacity >> 1)`).
* **Array Copying:** Memory reallocation uses `System.arraycopy()` via `Arrays.copyOf()`, which copies elements directly at the native OS memory level.

---

### 4. Insertions, Deletions, and Shifting

* **Positional Add (`add(index, element)`):**
* Checks bounds (`index >= 0 && index <= size`).
* Shifts elements starting at `index` one position to the right via `System.arraycopy()`.
* Inserts the new element at `index` and increments `size`.
* Time Complexity: **$O(n)$** due to shifting.


* **Removal (`remove(index)`):**
* Calculates `numMoved = size - index - 1`.
* Shifts elements to the left by one position.
* Sets the last slot `elementData[--size] = null` so the **Garbage Collector** can reclaim the dereferenced object.
* Time Complexity: **$O(n)$**.



---

### 5. Fail-Fast Iterators (`modCount`)

`ArrayList` tracks structural modifications (adding, removing, resizing) using an inherited counter named `modCount`.

* Every time an iterator is created, it takes a snapshot: `expectedModCount = modCount`.
* During iteration (`next()`, `remove()`), it checks `if (modCount != expectedModCount)`.
* If another thread or code modifies the list structurally outside the iterator, it immediately throws `ConcurrentModificationException`.

---

### Performance Summary

| Operation | Time Complexity | Notes |
| --- | --- | --- |
| **`get(index)` / `set(index, val)**` | **$O(1)$** | Direct memory offset lookup |
| **`add(element)` (Append)** | **Amortized $O(1)$** | $O(n)$ only when array needs resizing |
| **`add(index, element)`** | **$O(n)$** | Requires right-shifting elements |
| **`remove(index)`** | **$O(n)$** | Requires left-shifting elements |
| **`contains(element)` / `indexOf**` | **$O(n)$** | Linear scan across array |
